Prior & Calibrated Buildout

Three documents each for synpmx_prior() and synpmx_calibrated(), an extra methods menu, and a renumbering — scoped into tranches before any of it was written, and amended as each one landed.

Governing decision

“synpmx_prior() and synpmx_calibrated() should take on roles in exactly the way that avatar and pmxmodel do. I expect these to be the workhorses of this package and other functions (even if written first) should follow their conventions.”

This settles the one open API question in the scope below and reverses its direction. All six generators agree on one thing — a pmx_roles() declaration governs the column names of the output — and the two workhorses are the reference implementations of that agreement, not exceptions to it. synpmx_empirical() needed nothing: it already writes under the source roles through .set_row_role() and restores the public schema, so this scope's guess that it would follow by construction had the direction backwards. Only synpmx_prior() and synpmx_calibrated() stood outside the convention, which is the pair named.

Menus, Numbering, README

Mechanical. The navbar numbers live in three text: fields and nothing else in the repository depends on them.

The new structure adds one menu and demotes PCA into it:

  • 1. PMXmodel and 2. AVATAR keep their own top-level callouts.
  • A Methods menu holds 3. PCA, 4. Prior and 5. Calibrated, each with Demo, Algorithm and Evaluation on public data.

The numbering groups by what a mode reads

The settled order is 1 PMXmodel, 2 AVATAR, 3 PCA, 4 prior, 5 calibration, 6 empirical. An earlier pass put PCA at 5, on prominence, and that broke something the old numbering was carrying: modes 1 to 3 read the study and rest on governance, modes 4 to 6 protect privacy more strictly. Two paragraphs and the distribution plot's linetype scale encode that split as a contiguous range, so PCA sits at 3 beside PMXmodel and AVATAR rather than beside the two modes it shares the Methods menu with. AVATAR moving from 3 to 2 is the only change from the numbering the methods article already used. synpmx_empirical() sits at 6 with no menu of its own, which is defensible only as a deliberate choice.

The README's three-plus-three split stops being true

The methods section reads “Three synthetic data generators read a dataset” and “three additional generation algorithms … where data crosses a trust boundary”. Once prior and calibrated carry full article sets and take roles like the others, that framing misdescribes the package. AGENTS.md puts README rewrites behind explicit approval, so the wording goes to Andy rather than into a commit.

Roles on the Public-Model Modes

The governing decision, implemented. It landed before the four documents in tranche 3, because those documents show the call signature.

synpmx_avatar(), synpmx_pca() and synpmx_model() return the source study's own columns, so a single pmx_roles() serves both sides of compare_pmx_distributions(source, synthetic, roles) and synpmx_scorecard(source, synthetic, roles). synpmx_prior() and synpmx_calibrated() returned a fixed schema instead — pmx_generated_roles(), which is ID/TIME/NTIME/TAD/OCC/DV/AMT/RATE/EVID/CMT/DVID/MDV/CENS/DOSE. That is now the default rather than the only possibility.

One argument, two directions

synpmx_calibrated() already accepted roles and used it to read data; the same declaration now names the output columns too, so its signature did not change at all — only what the argument governs. synpmx_prior() reads no data, so its new third argument is purely a statement about the output: it prescribes a schema rather than describing one. The roxygen says so under its own heading, because a reader who has met the other three generators will assume roles always describes an input.

Honouring a declaration means refusing one you cannot honour

The first working version handed back a table that failed validate_pmx() under the very roles it was given: the declaration named a WT covariate, and these modes draw a covariate only from a public distribution they were handed. synpmx_avatar() never does that, so .reject_unfillable_roles() refuses up front and names what is missing — a covariate with no pmx_covariates() to draw it from, or a column such as ADDL that no structural model and protocol can produce. The default roles name only fillable columns, so this is reachable only from a real study's declaration.

Two smaller things the implementation settled. The rename walks the generated table's own columns rather than the role list, so column order is unchanged from what the generator produced — the first version walked the roles and moved RATE four places. And pmx_roles() deliberately permits one collision, cmt and dvid on one column, because NONMEM's CMT does both jobs; there the generated CMT already tells the endpoints apart, so the separate endpoint key is dropped rather than written over the same column twice.

What moved

  • R/generate_structural.R.rename_to_roles(), .reject_unfillable_roles(), and a roles argument on .generate_structural()
  • R/synpmx.Rsynpmx_prior() gains roles as its third argument; roxygen for all three public-model modes
  • R/calibrate.Rthe release carries the declaration, so synpmx_generate() reproduces the same schema later

No existing caller needed changing: every one passed pmx_generated_roles() or nothing. synpmx_empirical() needed nothing either, as the decision block above records.

The payoff is tranche 4: the five-step survey shape transfers without a column-mapping layer in each article and without a second roles argument on the comparison functions.

Reference Covariate Distributions

Came out of tranche 2's refusal. A mode that reads nothing can only draw a covariate from a distribution it was handed, and there was no way to state one.

The old declaration drew Normal(midpoint(range), diff(range) / 6) clipped, and uniform over levels for a categorical. So a plausible weight bound of c(40, 130) gave a symmetric distribution centred on 85 kg, and a four-level race column came out 25 per cent each. The defect underneath is that the clipping bound and the dispersion were the same number, so widening the bound for safety widened the distribution with it.

The spread transfers between populations and the median does not

Measured across the adult studies in the public-data surveys, body weight holds a coefficient of variation of 14 to 18 per cent while its median moves by a factor of 1.7 — from about 70 kg in a healthy-volunteer study to about 117 in a cohort selected for obesity. So a catalogue can own the shape and the spread, and the median is the argument it has to expose. Age and sex are not population constants at all: the same surveys run at ages centred on 31, 46 and 61 years and sex splits of 87/13, 50/50 and 70/30, which is decided by inclusion criteria and by where a trial enrolled. Those entries exist to put a column in the table, and the documentation says so rather than calling them reference values.

What the numbers are

Round values for a broad adult population, carrying a source that reads “a package default, not measured from any study” — the same stance the methods article takes on the built-in structural models. No citation is attached that could not be checked. Paediatric and neonatal cohorts are out of scope and sent to pmx_covariate(), because pheno_sd's 1.3 kg neonates are three orders of magnitude from anything an adult catalogue can say. Units are the other trap: mavoglurant records height in metres and nimoData in centimetres, which is how a generated column ends up wrong by a factor rather than by a little, so pmx_covariate_reference_table() exists to be read first.

  • R/covariates.Rmedian, cv, distribution, prob and integer on pmx_covariate(); pmx_covariates_reference() and pmx_covariate_reference_table() over ten covariates
  • tests/testthat/test-covariates.R43 checks, including that a range alone still behaves exactly as before, and that the reference median stays within 15% of the ordinary adult cohorts and outside it for the obese and neonatal ones
  • vignettes/articles/data-elicitation.Rmdthree more interview questions — inclusion criteria, enrollment targets, units — and a section on declaring a distribution without reading data
  • _pkgdown.ymlthe two new exports in the reference index, which build.sh checks

Rather than write the per-dataset medians into prose, which checklist item 9 in the writing guide rules out, the claim behind the catalogue is a regression test. That is also what stops the reference value drifting away from the populations it says it covers.

Four Demo and Algorithm Pages

Mostly consolidation. The prose for all four exists, scattered across the methods article, three privacy articles and roxygen.

prior-demo is the cheapest of the six documents

scripts/example_prior_pyrazinamide.qmd is already a 267-line worked prior example: a public specification, one unit conversion, generation, and a check back against the specification. Promoting it to a vignette is front matter and availability guards. It compiles nothing and reads no stored fit, so R CMD check can execute it — unlike pmxmodel-demo.Rmd, which knits against a fit built by build-model-fits.R.

prior-algorithm will be short, and that is the subject's doing

synpmx_prior() is a thin wrapper over .generate_structural(): no inference step, and nothing that reads data. The content is the catalogue — seven linear PK forms (1cmt_iv, 1cmt_oral, 1cmt_infusion, 2cmt_iv, 2cmt_oral, 1cmt_mixed, 2cmt_mixed) and four PD forms (none, constant, linear, exponential) — plus superposition, the design grammar, dropout, the assay limit and CENS, the output schema, and what the catalogue cannot express. Next to a 42 KB pmxmodel-algorithm.Rmd it will look thin.

calibrated-algorithm has mechanism, and three articles already carry it

The bounded multiplicative correction, clipping to the public prior, calibrated noise, the two released numbers, and pmx_preflight()'s f = d / (epsilon * N) are real mechanism worth a reference page. But feasibility.Rmd, privacy-background.Rmd and privacy-argument.Rmd cover much of it. The work is deciding what moves and what is cross-linked, not new derivation.

calibrated-demo runs on the site, with two caveats in every chunk

Every chunk needs synpmx_enable_dp_engines() and backend = "public", public_source = TRUE, since the demonstration datasets are public and no differential-privacy claim can attach to them. OpenDP 0.15.1 resolves locally and is listed in .github/workflows/pkgdown.yaml, so execution is not a risk. The maintenance status — complete and tested, not under active development, carrying open findings, not independently privacy-audited — has to appear on each new page, or promotion into a menu reads as a promotion of trust.

The Two Public-Data Articles

Unblocked on the API by the governing decision. Two obstacles survive, and the second one says the article as specified is the wrong shape.

  1. The output schema closed

    The five-step contract in AGENTS.md passes one roles to both the generator and the comparison functions, and tranche 2 made prior and calibrated honour it. Verified on theo_md: the calibrated output carries the study's own seven columns and synpmx_scorecard(theo_md, calibrated, theo_roles) scores twenty rows from one declaration. Nothing about the survey's shape is blocked any more.

  2. Every dataset needs a hand-elicited model and design

    These modes infer nothing, so each dataset needs a pmx_structural_model() and a pmx_trial_design() with a citable source that is not the data. Against the ten datasets in the existing surveys, the catalogue expresses five cleanly, two in part, and three not at all.

    What the built-in catalogue can say about each dataset in the existing surveys. Design grammar covers parallel dose levels, within-subject escalation, infusion duration and stated dose times; it has no form for a dose reduction triggered by a patient's own response.
    Dataset Expressible What decides it
    mixroute_simyes1cmt_mixed, and the generating truth is known, so the public model needs no invention
    theo_mdyes1cmt_oral, published population PK, PK only
    pheno_sdyes1cmt_iv, published neonatal phenobarbital model
    mavoglurantyes2cmt_iv, published model
    nimoDatayes1cmt_infusion covers ten infusions recorded as actuals
    case1_pkpdpartialPK fine; the PD endpoint is signed and runs to −621, which only linear reaches, and crudely

    No covariate effects, no inter-occasion variability, no additive residual error and no ODEs, which the methods article already states. So the survey is five or six datasets rather than nine or ten, and each one needs a literature source defended in prose.

  3. The article would measure the elicitation, not the algorithm

    For AVATAR, PCA and PMXmodel a poor scorecard is the generator's fault. In prior mode every mismatch is the assumed model's fault, which the methods article says plainly about theophylline: an assumed clearance of 6 L/h is about twice the truth, and the concentrations run low. Ten datasets would produce ten variants of “the prior was wrong by this much”.

    The article that answers a question instead: two datasets where the truth is known — mixroute_sim and onc_sim — plus a sensitivity axis. How wrong can the assumed clearance be before the output stops being usable for code development? For calibrated the axis is epsilon against cohort size, which is largely feasibility.Rmd's existing ground and would have to be divided with it.

Not in scope

  • No fingerprint document. pca-fingerprint.Rmd and pmxmodel-fingerprint.Rmd read out a fitted object. Prior and calibrated fit nothing worth reading out — calibrated releases two numbers, and they already print with the release attribute.
  • PCA keeps its three documents. They are the template the new pages copy, so they stay intact through tranche 3 whatever the method's standing.
  • No new menu for synpmx_empirical(). It becomes mode 6 with an article-level treatment only inside synpmx-methods.Rmd.
